## Changes and reasons

1. **Native configuration race:** `NetworkController.apply` now waits for the in-flight native configuration before comparing current settings. It loops after success so settings changed during the request win, coalesces concurrent identical requests, and clears the handle after failure so retries remain possible.
2. **Dropped source refresh:** `TokenPricer` retains a pending forced refresh and runs it in cleanup after the active branches settle. Multiple pending requests coalesce; the follow-up reads the latest source. Obsolete branches still cannot publish prices.
3. **History completeness race:** `WalletService.loadHistory` returns a `HistoryResult` record containing rows and the request's partial flag. The shared `lastHistoryPartial` field is removed. The gateway and sync controller carry the record through the asynchronous joins; the activity screen's adapter also consumes it directly. This fixes the out-of-band status at its source, including the wait for pending transactions.
4. **Assets empty state:** the empty-state condition reads the same live `holdings` as the token sections. Tests cover empty and nonempty stale route arguments, live token arrival, and reset.
5. **Stale reports:** the initial report is explicitly superseded by Part 1 completion in `c839397`; its remaining investigation is labeled historical. Both reports identify the completed commits and remove links and retention claims for deleted evidence directories. No dumps were restored.
6. **Documentation coverage:** added purpose-oriented doc comments to touched configuration, pricing, wallet-generation/status, cache adapter, history adapter, Assets build, and status-line factory functions. No unrelated functions were documented. CodeRabbit's exact coverage percentage was not independently recalculated locally.
